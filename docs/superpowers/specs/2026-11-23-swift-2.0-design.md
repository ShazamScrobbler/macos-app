# ShazamScrobbler 2.0 — Swift rewrite, multi-service scrobbling

Date: 2026-11-23 · Status: design approved in conversation, spec awaiting review

## 1. Why

- **Last.fm API change (reported for 2026-12-01):** API keys only work while the owning account has Last.fm Pro. 1.x ships one shared key (`LastFmConstants.m`), so every user breaks at once if that account isn't Pro. Not yet confirmed from a Last.fm primary source.
- **Free alternatives exist:** ListenBrainz (open source, MetaBrainz) and servers speaking its API (Maloja, Koito, multi-scrobbler); Libre.fm speaks the Last.fm API.
- **1.x is aging:** unmaintained `LastFm` pod, CocoaPods trunk going read-only, deprecated launch-at-login API, Apple-Silicon-only build (#46), plain-text session in `NSUserDefaults`, and several long-standing bugs (§9).

Decision: skip a 1.x patch and go straight to a Swift 2.0. Last.fm scrobbling via the shared key may be down between 2026-12-01 and the 2.0 release unless the key-owning account takes Pro.

## 2. Goals

1. Scrobble Shazam for Mac tags to **any number of accounts at once**, across two protocol families:
   - **Audioscrobbler 2.0** (Last.fm, Libre.fm, custom server URL) with either the **built-in key** or the **user's own key + secret**.
   - **ListenBrainz** (listenbrainz.org, or a custom URL for Maloja/Koito/multi-scrobbler) with a user token.
2. Keep every 1.x behaviour (§5) and fix every previously reported issue (§9).
3. Follow current Apple practice for a menu bar agent app: live-updating menu, SwiftUI settings, Keychain, `os.Logger`, notarized universal build, Sparkle updates.
4. Upgrade 1.x users without re-login.

Non-goals: Windows (#29), iOS (#35), macOS < 12 (#27), App Store distribution (impossible: sandbox), notarization (no Developer ID), suppressing Shazam's own notifications (macOS does not allow it).

## 4. Architecture

```
ShazamLibrary ──tags──▶ ScrobbleEngine ──decisions──▶ StateStore ◀──▶ Delivery ──▶ Scrobbler (per account)
      ▲                       ▲                            │                         ├─ AudioscrobblerClient
 FolderWatcher           Clock (injectable)                ▼                         └─ ListenBrainzClient
                                                     AppModel (@MainActor) ──▶ MenuController / Settings UI
```

| Unit | Responsibility | Depends on |
|---|---|---|
| `ShazamLibrary` | Read-only access to `~/Library/Group Containers/4GWDBCF5A4.group.com.shazam/com.shazam.mac.Shazam/ShazamDataModel.sqlite`. Validates schema, returns `[ShazamTag]` (pk, date, artist, title, album?). Dates: Core Data reference date (`timeIntervalSinceReferenceDate`). Reports `LibraryStatus` | SQLite3 |
| `FolderWatcher` | `DispatchSource` vnode watch on the **directory** (and parent, to survive delete/recreate) + 0.5 s debounce. Emits "changed". | — |
| `RescanScheduler` | Triggers scans on: watcher event, 60 s timer, `NSWorkspace.didWakeNotification`, network becoming available, menu opening | FolderWatcher, NWPathMonitor |
| `ScrobbleEngine` | Pure logic: given new tags, settings, clock → per-tag decisions (now playing, schedule scrobble, too short, skip, dedupe). No I/O | Clock |
| `StateStore` | App's own SQLite at `~/Library/Application Support/ShazamScrobbler/state.sqlite`: tags seen, per-(tag, account) delivery status, user exclusions, per-account markers. Schema-versioned migrations | SQLite3 |
| `Scrobbler` protocol | `validate()`, `nowPlaying(_:)`, `scrobble(_ batch:)`, `isOtherPlayerActive()`, `remove(_:)?` | — |
| `AudioscrobblerClient` | Audioscrobbler 2.0: `auth.getToken`, `auth.getSession`, `track.updateNowPlaying`, `track.scrobble` (≤ 50 per batch), `user.getRecentTracks` (limit 1, `nowplaying` attr). Request signing per Last.fm spec. JSON (`format=json`) | URLSession, CryptoKit |
| `ListenBrainzClient` | `GET /1/validate-token`, `POST /1/submit-listens` (`playing_now`, `single`, `import`), `GET /1/user/{name}/playing-now`, `POST /1/delete-listen` | URLSession |
| `AccountStore` | Accounts (id, kind, display name, server URL, key mode) in UserDefaults; secrets (session key, token, own API secret/key) in Keychain (`kSecClassGenericPassword`, service = bundle id, account = account id + field) | Security |
| `Delivery` | Per-account worker: picks due items, batches, sends, classifies results (§7), schedules retries with backoff | StateStore, Scrobbler |
| `AppModel` | `@MainActor` observable state for the UI: library status, now playing (+ deadline), 20 recent tags with per-account status, account health, pause state | all above |
| `MenuController` | Builds and updates the `NSMenu` (§6) | AppModel |
| `SettingsWindow` | SwiftUI tabs General / Accounts; Add Account sheet; standard About panel | AppModel, AccountStore |
| `Notifier` | `UNUserNotificationCenter` (optional, §6.4) | — |
| `Updater` | Sparkle `SPUStandardUpdaterController` + "Check for Updates…" | Sparkle |

Concurrency: SQLite readers and network clients run off the main actor (actors / `Sendable` values); all UI mutation is `@MainActor`.

## 5. Scrobbling rules (carried from 1.x, made explicit)

1. **New account marker = now.** A freshly connected account only receives tags detected after it was added (#25). Optional "Also send tags from the last N days" in the add flow is **not** in 2.0.
2. **Marker is the tag date**, not Shazam's `Z_PK` (survives Shazam DB recreation, #28 workaround). Dedupe key: (date, artist, title).
3. **Newest tag = probably still playing.** Send now playing to every active account; schedule scrobble at `tagDate + minPlayTime` (default 45 s, setting 30–240 s).
   - A newer tag before the deadline → previous becomes `tooShort` (⊘ "not played long enough") (#16).
   - Re-send now playing every 4 min until the next tag or 10 min cap; send it **without a duration** (fixes #47).
4. **Other player active (#22):** before now playing, per account ask `isOtherPlayerActive()`. If true for that account only, that account's status is `skipped(otherPlayer)`; other accounts proceed.
5. **Older tags** (backlog) are scrobbled immediately in batches, oldest first.
6. **Repeat tags (#42):** same artist+title within 10 min of the previous tag of that song → merged into the first (no second scrobble).
7. **Pause (#2, #17, #28):** menu "Pause Scrobbling" (⌘P). Setting "While paused": **Ignore new tags** (default, → `skipped(paused)`) or **Keep them for later**. "Skip N Waiting" action marks all `waiting` items skipped.
8. **Don't Scrobble / Scrobble Anyway** per song, per all accounts, from the song submenu or notification. "Scrobble Anyway" on a `tooShort`/`skipped` item queues it.
9. **Album** sent when present (#37).

Delivery status per (tag, account): `waiting → nowPlaying → sending → scrobbled | ignored(reason) | skipped(reason) | tooShort | held(accountProblem) | retry(attempt, nextAt)`.

Song submenu: one row per account with status + time/reason; separator; Don't Scrobble ↔ Scrobble Anyway; Remove from ListenBrainz (ListenBrainz accounts, scrobbled items); Open Last.fm Library (Audioscrobbler accounts); Copy "Artist – Title".

Aggregate icon on the song row: ✓ all done; ◐ some accounts done/some not; ⏳ waiting/retrying; ⊘ skipped/too short/ignored everywhere. Icons are SF Symbols with accessibility descriptions; titles truncated in the middle at ~60 chars with full text in tooltip.

**Live update rules (#8):**
- Menu built once; updates mutate existing items (`title`, `image`, `state`, `isHidden`, `toolTip`, submenu contents). No insert/remove at runtime → no index drift (c71b1cd, dc732dd).
- Row mapping is a pure function `render(model) -> [SlotContent]` diffed against current slots; only changed slots are touched. Unit-tested.
- All updates on main actor; countdown `Timer` added to `RunLoop.main` in `.common` mode; started in `menuWillOpen`, stopped in `menuDidClose`.
- `menuWillOpen` also triggers a rescan.

### 6.3 Settings window
Single `NSWindow` hosting SwiftUI `TabView`, reused (never duplicated). Opening: `NSApp.activate(ignoringOtherApps:)` on 12–13, `NSApp.activate()` on 14+, then `makeKeyAndOrderFront`. Closing it does not quit the app.

- **General:** Launch at login; While paused (Ignore / Keep); Minimum play time (stepper, 30–240 s, default 45); Notifications (Off / Now playing with "Don't Scrobble" button); Automatically check for updates (Sparkle).
- **Accounts:** list (service icon, name, server host, health badge, waiting count), `+` / `−`, double-click → detail sheet (Sign In Again, Change Key…, Remove).

**Add Account sheet:**
- Service picker: Last.fm · Libre.fm · ListenBrainz · Custom (Last.fm-compatible) · Custom (ListenBrainz-compatible).
- Audioscrobbler: key mode radio **ShazamScrobbler's key** / **My own key** (key + secret fields, "Get an API key" → `https://www.last.fm/api/account/create`; hidden for Libre.fm unless custom). Sign in via browser: `auth.getToken` → open `{web}/api/auth/?api_key=…&token=…` → poll `auth.getSession` every 3 s up to 5 min → "Signed in as X". Cancel / Try Again. Errors shown verbatim from the server (#39). If the server does not support web auth (custom servers), fall back to username/password `auth.getMobileSession` over HTTPS — password never stored.
- ListenBrainz: server URL (default `https://api.listenbrainz.org`), token (secure field), "Get your token" → `https://listenbrainz.org/settings/`; validated on paste → "Signed in as X".

### 6.4 Notifications (#1)
Off by default. When on: notification for the now-playing tag with action **Don't Scrobble** (valid until the scrobble deadline), and a notification when an account enters a problem state (once per state change). Permission requested only when the user turns the setting on.

### 6.5 Shazam access: guided Full Disk Access (verified 2026-11-23 on macOS 27.0.1)

**Findings (probe apps + 1.4.0, logs from `tccd`/`sandboxd`):**
- macOS 15 put group containers under SIP/app-data protection. On macOS 27 a non-owner read of Shazam's container is checked as `kTCCServiceSystemPolicyAppDataDetailed`, which **"does not allow prompting"**: silent denial, no dialog, for any signing type.
- **1.x broke with the macOS 27 upgrade (installed 2026-10-12).** Same 1.4.0 binary: without FDA → `AppDataDetailed` denied, `[database open]` fails, `ShazamController.init` still returns true → empty menu, no error. With FDA → `AllFiles authValue=2`, reads the DB, scrobbled the backlog (lastScrobble 11938 → 12026).
- **Full Disk Access is the only working route** and it does unlock Shazam's container on 27.0.1.
- **FDA survives updates only with a stable signing identity:** self-signed build 2 (never added) read the DB using build 1's grant; ad-hoc build 2 was denied. TCC stores the designated requirement — `identifier + certificate leaf` (stable) vs `cdhash` (changes every build).
- Side effect seen on 1.x: a "would like to access files on a network volume" prompt caused by its old login-item code touching a mounted SMB share. 2.0 must not enumerate login items or volumes.

**Design:**
- Never rely on a prompt. Detect `accessDenied` by the open/read error (`EPERM`/`SQLITE_AUTH`/`SQLITE_CANTOPEN` with errno EPERM), never by `fileExistsAtPath` (metadata is still readable when content is not).
- First-run / denied state shows a **setup window**: one sentence on why ("macOS only lets apps read Shazam's history with Full Disk Access"), what we read (the exact path), a button **Open Full Disk Access Settings** (`x-apple.systempreferences:com.apple.settings.PrivacySecurity.extension?Privacy_AllFiles`), a draggable app icon to drop into the list, and a live status that flips to ✓ when access works (rescan every 2 s while the window is open). No restart needed in the common case; if the live check hasn't flipped within 5 s of the FDA toggle, show **Relaunch ShazamScrobbler** (macOS may also offer "Quit & Reopen"). Whether FDA applies without relaunch on 12–27 is unverified — test it.
- Link to `SECURITY.md` (§13) from that window.
- If a future macOS also blocks FDA here, the same state shows "macOS blocked access" with the log line, instead of an empty menu.

States shown in the menu status row and Settings:
- `ok`
- `notInstalled` → "Install Shazam" (App Store link)
- `noLibraryYet` → "Waiting for Shazam's first tag" (#36), auto-recovers
- `accessDenied` → "Set Up Access…" opens the setup window above; auto-recovers on next successful scan
- `unsupportedSchema` → "This Shazam version isn't supported yet" + logged schema (#32)

## 7. Delivery and errors

- Batches: Audioscrobbler ≤ 50 per `track.scrobble`; ListenBrainz `import` ≤ 100 per request (and under the documented payload limit).
- Retry backoff: 1, 2, 4, … min, capped 60 min, ±20 % jitter. Immediate retry on new tag, network up, wake, account fixed.
- Accounts are independent: one failing account never blocks another.

| Signal | Classification | Effect |
|---|---|---|
| Last.fm error 9 / LB 401 | `signedOut` | Items `held`; "Sign In Again"; notify once |
| Last.fm error 10, 26 (and the code the Pro cutoff uses, to confirm at implementation) | `keyUnusable` | Items `held`; "Key not working — Last.fm may require Pro for this key" + **Use My Own Key…** (built-in key) or **Change Key…** |
| Last.fm 11, 16; HTTP 5xx; timeouts; offline | transient | `retry` |
| Last.fm 29; LB 429 | rate limited | wait `X-RateLimit-Reset-In` if given, else backoff |
| Last.fm `ignoredMessage` 1–4 | ignored | `ignored(reason)` shown in submenu (#31 visibility) |
| Last.fm `ignoredMessage` 5 (daily limit) | deferred | retry after next UTC midnight |
| Tag > 14 days old for Audioscrobbler | ignored locally | `ignored(tooOld)`; ListenBrainz unaffected |
| LB 400 | permanent | `ignored(server message)` |

## 8. Migration from 1.x

On first 2.0 launch, if `session` exists in the 1.x defaults domain:
1. Create a Last.fm account with built-in key, username from `username`, session key moved to Keychain.
2. Marker = date of tag `lastScrobble` (looked up in Shazam DB) or now if not found.
3. `notToScrobble` pks → exclusions by (date, artist, title).
4. `scrobbling == 0` → paused, "While paused = Keep" (preserves 1.x semantics for that user).
5. Remove old keys; old LaunchAtLogin entry removed and re-registered via `SMAppService` if it was on.
Bundle id unchanged so defaults and Sparkle continuity hold.

## 11. Release

GitHub Actions on tag: build universal Release, sign with the self-signed certificate (hardened runtime), DMG, Sparkle `generate_appcast` with EdDSA key, upload to GitHub Release, publish appcast. Secrets (certificate .p12 + password, Sparkle EdDSA private key) in GitHub Actions secrets. CI also runs tests on every PR (macOS runner). 1.x users need one manual download to reach 2.0 (1.x has no updater); README and the GitHub release say so.

**Why a stable self-signed certificate (not ad-hoc) — required, verified:** Full Disk Access and Keychain access are tied to the app's designated requirement. Ad-hoc → `cdhash` → every update silently loses FDA (proven in §6.5). One self-signed identity reused for every release → `identifier "ShazamScrobbler" and certificate leaf = H"…"` → FDA carries over (proven). Losing the certificate's private key = every user redoes FDA setup once, so: store the .p12 in GitHub secrets **and** an offline backup; validity 20 years. It does not satisfy Gatekeeper.

**First-launch instructions (README, DMG background, release notes):** the app is not notarized, so macOS blocks the first open. Steps: open the app once → System Settings › Privacy & Security › "Open Anyway" → confirm. (Right-click → Open no longer bypasses this on macOS 15+.) Include screenshots. Sparkle-installed updates do not repeat this.

**Later option:** an Apple Developer Program membership ($99/yr) would allow Developer ID signing + notarization and remove the first-launch steps; the release workflow keeps signing in one step so it can be swapped. Homebrew cask is out of scope (Homebrew is removing casks that fail Gatekeeper).

**Code-signing note for implementation:** Keychain items created with the self-signed identity; verify on a clean machine that an update signed with the same certificate reads existing items without a prompt.

## 13. Trust: proving the binary matches the source and reads only what we claim

FDA can't be scoped to one folder, so the app must earn it:

| Layer | Proves | How a user verifies |
|---|---|---|
| Build provenance — `actions/attest-build-provenance` on the release DMG | This DMG was built by GitHub Actions from commit X by this workflow, never on a laptop | `gh attestation verify ShazamScrobbler-<v>.dmg -R ShazamScrobbler/macos-app` |
| Small audit surface | Only `ShazamLibrary` touches files outside the app's own container; it opens one fixed path read-only and runs fixed SQL | CI check fails the build if any other module uses `FileManager`/`open`/`sqlite3_open` on non-app paths, or if `ShazamLibrary` imports networking |
| Observable behaviour | Only Shazam's DB is opened; only configured servers + the Sparkle appcast are contacted; no analytics | `SECURITY.md` recipes: `sudo fs_usage -f filesys -w <pid>`, LuLu/Little Snitch |
| Release integrity | Updates not tampered with | Sparkle EdDSA, SHA-256 in release notes, pinned `Package.resolved` |
| Build it yourself | Independent of our binaries | README build steps; user grants FDA to their own build |

Reproducible builds are not a goal (Xcode output and signatures aren't byte-stable); provenance attestation is the substitute.
