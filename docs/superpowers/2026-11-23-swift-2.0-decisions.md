- Task 4: Ruling: (plan-mandated I1) exclusion only overrides non-final states (nil, nowPlaying, waiting, retry, held); a new excluded tag that is a duplicate stays skipped(.duplicate); un-excluding skipped(.user) re-evaluates like a new row (duplicate → skipped(.duplicate), else playState); only `forced` revives tooShort/other skips — spec §5.8 limits Scrobble Anyway to explicit force, Review Focus 3 forbids double scrobbles — cost if wrong: un-excluding a paused-skipped tag now re-evaluates instead of staying skipped
- Task 4: Ruling: (plan-mandated I2) a tag is a duplicate only if the previous *play* (last non-duplicate tag) is the same song within 600 s — A-B-A otherwise loses the real play of A and scrobbles a 10 s B; narrows spec §5.6 wording ("previous tag of that song") — update spec §5.6 at the end — cost if wrong: a song interrupted by a short misidentification could scrobble twice (A tooShort is prevented, so practically A once)
- Task 4: Ruling: add public init to EngineOutput and a doc comment on EngineInput.tags (callers must include ≥600 s of history before the oldest cursor) — cheap, prevents cross-module friction — cost if wrong: none
- Task 4: Ruling (carry to Task 12): ScanCycle reads Shazam tags since `min(cursors) - EngineSettings.duplicateWindow` (engine only creates rows for tags > each cursor, so extra history is harmless) — duplicate/following detection needs the preceding play — cost if wrong: slightly larger query each scan
- Task 4: Ruling: duplicates chain on the last sighting of the current play (not the play's first tag) — re-review found A@0,A@500,A@1000 split into two scrobbles under the round-1 rule — cost if wrong: a song genuinely replayed within 10 min of its last sighting merges into one scrobble
- Task 5: Ruling: (plan-mandated I1) StateStore holds a private NSRecursiveLock across every public method — it is shared by ScanCycle, Delivery and MainActor callers and the SQLite transaction doesn't lock across its body — cost if wrong: slight contention on a tiny DB
- Task 5: Ruling: (plan-mandated I2) hold() stays row-based; documented that an account problem with nothing queued is re-reported by Delivery each run rather than persisted — nothing is lost since nothing is queued — cost if wrong: problem row disappears from the menu until the next send attempt
- Task 6: Ruling (carry to Task 11): clamp server retryAfter in DeliveryPolicy.state to 5…3600 s — a 0/negative X-RateLimit-Reset-In would otherwise make AppModel's wake timer retry every 0.5 s — cost if wrong: honours a server asking for <5 s slightly late
